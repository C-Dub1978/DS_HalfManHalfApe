# HmhaIcon

```html
<hmha-icon name="check" size="md" />
```

A custom element, not an attribute directive — no native element covers
"inline vector glyph." Markup is bundled at build time from a **generated**
registry (`icon-registry.ts`); there is no sprite fetch and no runtime HTTP
request, and the file is not checked in (see below).

## Inputs

| Input | Type | Default | Notes |
| --- | --- | --- | --- |
| `name` | `HmhaIconName` (required) | — | One of ~120 curated icon names — see `scripts/icons/allowlist.json` for the full list. |
| `size` | `'sm' \| 'md' \| 'lg'` | `'md'` | Reflected as `data-size`; drives `--hmha-icon-size`. |

## Component tokens — the override API

| Token | Default | Set by |
| --- | --- | --- |
| `--hmha-icon-size` | `var(--hmha-icon-md)` | base; re-pointed per `data-size` |

Set `--hmha-icon-size` directly on the host for a one-off size the `sm`/`md`/`lg`
scale doesn't cover; prefer the `size` input otherwise.

## Colour

The icon has no colour token of its own — it renders with `stroke="currentColor"`
and inherits `color` from its CSS context. Put it inside a tone-bearing
ancestor (a `button[hmhaButton]`, a coloured text run) rather than setting
colour on the icon directly.

## Accessibility

The inner `<svg>` is always `aria-hidden="true"` — `HmhaIcon` is decorative by
design. For an icon-only control, put the accessible name on the *interactive*
element (`aria-label` on the button), not on the icon.

## Where the icons come from

The registry is generated by `scripts/generate-icons.mjs` from two inputs:

- `scripts/icons/allowlist.json` — the curated list of icon names, checked
  into git. This is the reviewable source of truth; a PR that adds an icon
  touches this file, not the generated one.
- [`lucide-static`](https://lucide.dev) (ISC licence) — the actual SVG
  source, pinned as a devDependency. Lucide's own stroke-based style
  (`stroke="currentColor"`, `fill="none"`, 2px stroke, round caps/joins,
  24x24 viewBox) is what `icon.ts`'s wrapping `<svg>` carries, so registry
  entries only need to be the inner `<path>`/`<circle>`/... markup.

Run `npm run icons` to regenerate `icon-registry.ts` after editing the
allowlist — it is gitignored, not checked in, exactly like
`libs/tokens/src/lib/hmha-tokens.ts`. It also runs as part of `npm run ci`.

## Adding an icon

Add the Lucide filename (from `node_modules/lucide-static/icons/`, no
extension) to the `icons` array in `scripts/icons/allowlist.json`, then run
`npm run icons`. The `HmhaIconName` union updates automatically — it is
derived from the registry's keys. To publish an icon under a different name
than Lucide uses (a rename you want to insulate consumers from, or to match
an existing name), use `{ "name": "...", "source": "..." }` instead of a bare
string — see the `close`/`spinner` entries for examples. The generator fails
loudly if a requested Lucide filename doesn't exist, so a typo can't silently
produce a missing icon.

## Unsupported

`::ng-deep`, selectors targeting internal DOM, or overriding by specificity —
per the encapsulation contract in `DECISIONS.md` fork 05. Set `--hmha-icon-size`
instead.
